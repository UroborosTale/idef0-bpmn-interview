# Процессная модель (приложение process-modeling-app)

Эти правила — для задач про **процессную модель** (интервью, IDEF0, BPMN, роли, продукты). Для правок кода приложения они
не действуют.

- Моделью управляет приложение; она доступна только через MCP-сервер `process-modeling`. Не правьте модель, JSON-файлы или
  базу напрямую — отправляйте предложения (`propose_patch`).
- **Вы только предлагаете — применяет аналитик.** Предложение отправлено — значит, ваша часть сделана; решение смотрите через
  `list_proposals`. Отказ с причиной учитывайте в следующем предложении.
- Перед первым предложением вызовите `get_conventions`, затем `get_model` нужной сессии.
- Предложения небольшие, по одной теме, с обоснованием (`rationale`): цитата интервью, правило Соглашения или замечание проверки.
- В `agent` указывайте свою роль: методолог, моделист, нормоконтролёр, интервьюер, аналитик.
- Цитата в `source` — только из `get_fragments`. Чего нет в тексте и в модели, не выдумывайте: оформляйте как вопрос аналитику.
- Отвечайте аналитику по-русски, коротко: что сделано, что предложено, что неясно.
- Смотрите в ответ `propose_patch`: если предложение вносит новые замечания проверок — доработайте его.
- Диаграммы, коды и раскладку рисует приложение; вам их строить не нужно.

## Роли
Каждая роль описана отдельной инструкцией (в Cline — workflow, вызывается через `/`). Берите инструкцию своей роли и не
выходите за её границы; чужую работу поручайте через `create_task`.

| Роль | Инструкция | Для чего |
|---|---|---|
| методолог (главный агент) | `/methodologist` | Распределяет задания, хранит Соглашение, решает спорное |
| моделист | `/model-from-interview` | Строит модель по тексту интервью |
| нормоконтролёр | `/review-model` | Проверяет модель, исправляет механическое |
| интервьюер | `/interviewer` | Готовит вопросы для следующего интервью |
| аналитик | `/analyst` | Выводы по готовой модели: узкие места, дубли, улучшения |
