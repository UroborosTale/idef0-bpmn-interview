# Система построения моделей IDEF0 и BPMN по текстовому интервью

Веб-приложение, реализующее техническое задание: преобразование текстового интервью с владельцем бизнес-процесса в формализованные модели IDEF0 и BPMN 2.0, с трассировкой каждого элемента к исходному тексту.

## Состав репозитория

```
server/            — API-сервер (Express + TypeScript + SQLite), конвейер извлечения/валидации/генерации
server/src/shared/ — геометрия диаграмм, общая для сервера и редакторов в браузере
server/test/       — тесты (vitest)
web/               — веб-клиент (React + TypeScript + Vite), редакторы и просмотр моделей
desktop/           — настольная оболочка ProcessStudio (.NET 8 + WebView2 + встроенный Visio), см. docs/desktop-setup.md
docs/              — план по Business Studio 6, снятые типы BPMN, ручная приёмка, доступ агентов
docker-compose.yml — запуск обоих сервисов в контейнерах (НФТ-6)
```

## Архитектура (раздел 6 ТЗ)

- **Веб-клиент** — чат интервью, просмотр текста с трассировкой, студия с собственными редакторами BPMN и IDEF0 (декомпозиция вглубь), справочниками и отчётами, список пробелов, панель валидации, экспорт. Адреса страниц: `/s/<сессия>?tab=<вкладка>`.
- **API-сервер** — REST API, хранилище сессий (SQLite); вход по cookie для API (в веб-клиенте экрана входа нет).
- **Оркестратор LLM-конвейера** — `server/src/pipeline/extract.ts`: фрагментация → чанки → вызов LLM со structured output → проверка ответа (`llm/schema.ts`) → слияние и дедупликация сущностей. Обработка идёт фоновой задачей (`jobs.ts`).
- **Модуль валидации** — `server/src/pipeline/validate.ts` (BPMN soundness-lite, правила IDEF0, стиль наименований).
- **Модуль пробелов** — `server/src/pipeline/gaps.ts` (правила полноты, противоречия, неявные ветвления).
- **Модуль раскладки и генерации** — `server/src/pipeline/bpmn.ts` (BPMN 2.0 XML + раскладка ELK), `server/src/pipeline/idef0.ts` (IDEF0: A-0, A0, диаграммы декомпозиции, узловое дерево), `server/src/export/vsdx.ts` (Visio).
- **Принцип** (6.2): LLM только извлекает данные и формулирует факты с цитатами; нотации, раскладка и валидация строятся детерминированным кодом — LLM не участвует в генерации диаграмм.

Промежуточная модель — **Process Logic JSON** (раздел 5 ТЗ):
- TypeScript-типы + zod-схема: `server/src/types/model.ts`;
- публикуемый JSON Schema контракт: `GET /api/schema/process-logic/latest`.

## LLM-провайдер (ФТ-3, 6.3)

Провайдер подключаемый (`server/src/llm/provider.ts`), выбирается по переменным окружения:
1. `ANTHROPIC_API_KEY` — Claude (structured output через tool-use, `temperature=0`);
2. `LLM_BASE_URL` + `LLM_API_KEY` + `LLM_OPENAI_MODEL` — любой OpenAI-совместимый облачный провайдер (Mistral, Groq, OpenRouter, Gemini…);
3. иначе — **детерминированный офлайн-экстрактор** на правилах (`llm/mockProvider.ts`): работа без сети и тесты, качество ниже.

Процессы с признаком «конфиденциально» обрабатываются только локальным провайдером (`LOCAL_LLM_BASE_URL`, vLLM/Ollama) — во всех режимах: пакетная обработка, чат-интервью, мультиинтервью, верификация.

Вызовы LLM идут с таймаутом и повторами (429/5xx/обрыв), ответ проверяется: неверные элементы отбрасываются, ссылки на фрагменты сверяются с текстом, элементы с непроверенной цитатой становятся гипотезами. Сбой части текста попадает в проверки модели.

## Быстрый старт (разработка)

Требуется Node.js 20+.

```bash
npm install          # из корня: ставит зависимости сервера и клиента (workspaces)
npm run dev:server   # http://127.0.0.1:8787
npm run dev:web      # http://localhost:5173 (проксирует /api на сервер)
```

Ключи и настройки удобно держать в `.env` в корне (см. `.env.example`).

## Вход и безопасность

- В веб-клиенте нет экрана входа: приложение сразу открывает рабочие страницы. `AUTH_USERS` защищает API; если вход включён, cookie ставит `POST /api/auth/login` (так делают e2e-тесты).
- Пользователи задаются `AUTH_USERS=логин:пароль,логин2:пароль2`. Пароль лучше хранить хэшем: `npm run hash-password -w server -- <пароль>` → `AUTH_USERS=analyst:scrypt$…`.
- Без `AUTH_USERS` вход отключён, и сервер слушает только `127.0.0.1` (локальная разработка). Наружу (`HOST=0.0.0.0`) сервер стоит открывать только со входом.
- **Осторожно при включении входа:** без `HOST` при заданном `AUTH_USERS` сервер поднимается на `0.0.0.0`, то есть открывается всей сети (`server/src/index.ts`). Если нужен только локальный доступ, задайте `HOST=127.0.0.1` явно.
- **Настольное приложение при включённом входе сломается:** оболочка (`desktop/ProcessStudio`) обращается к API без заголовка авторизации, а её ручки не публичные — отвалятся выгрузка `.vsdx`, значки событий и приём правок из Visio. Подробности и список ручек — `docs/desktop-setup.md`. Агентам при этом нужен `AGENT_API_TOKEN`.
- **Ключ LLM в `.env`:** файл вне git, но ключ лежит открытым текстом. Храните его в менеджере секретов и ротируйте при подозрении на утечку. Помните, что при облачном провайдере текст интервью уходит наружу; для конфиденциальных процессов работает только локальный провайдер (НФТ-4).
- Без входа доступны только `/api/health`, `/api/schema/*` и ответы респондентов по персональной ссылке кампании (с ограничением частоты).
- CORS выключен (клиент ходит через прокси); чужие источники — `CORS_ORIGIN`.
- Вебхуки (карточка процесса, напоминания, уведомления) не уходят на внутренние адреса: имя хоста разрешается в IP, перенаправления не выполняются.
- Защита вебхуков от SSRF полная: IPv6 разбирается целиком (IPv4-mapped `::ffff:127.0.0.1`, NAT64, ULA, link-local, multicast, `198.18/15`), а адрес проверяется в самом разрешении имени при соединении — сокет открывается по проверенному IP, поэтому подмена ответа DNS между проверкой и соединением (DNS rebinding) невозможна.
- Встраивать страницы приложения в `iframe` можно только со своего источника (`X-Frame-Options: SAMEORIGIN` — так работает предпросмотр регламента). GET-запросы ничего не пишут в базу (cookie входа с `SameSite=Lax` уходит и при переходе по чужой ссылке); это проверяет тест `getReadOnly`. Ошибки асинхронных обработчиков перехватываются общим слоем и не роняют сервер, неверные по типу тела запросов получают 400/413.

## Студия — рабочее место аналитика

Вкладка «Модель → Студия» — единое окно в духе Business Studio, целиком внутри приложения:

- **Навигатор** слева — дерево как в Business Studio 6. Модель с кодом процесса — иерархия по кодам Соглашения: группа процессов (папка; поле «Группа процессов» в паспорте) → процесс `B002.00.00` (клик — IDEF0 процесса) → подпроцессы `B002.01.00` → операции `B002.01.01` → диаграмма BPMN операции (тот же код и название); подписи — сами коды. Модель без кода — номера блоков (A0, A1, A1.1) и общая схема BPMN. Справочники и отчёты — ниже. Клик по функции открывает её диаграмму и выделяет блок, двойной щелчок — декомпозицию; длинные названия прокручиваются по горизонтали. Выбранная на диаграмме функция (или операция, если выбран её шаг) сама раскрывает свёрнутые ветки и прокручивается в видимую часть; кнопка «Найти в навигаторе» (лента, «Вид») показывает в дереве выбранный элемент или текущую диаграмму, сбрасывая поиск. В свойствах функции и шага список **«Изображена на диаграммах»** (блок на диаграмме родителя, шаг общей схемы, декомпозиция, диаграмма BPMN операции) со ссылками; подтверждение удаления функции называет диаграммы, с которых уйдёт её блок, и те, что исчезнут вместе с ней. **Туннели стрелок IDEF0** (раздел «Туннель» в свойствах выбранной стрелки, поле функции `tunnels`): внешний вход, выход, управление или управление-данные можно пометить «у свободного конца» (нет на диаграмме выше) и/или «у блока» (нет в декомпозиции функции) — у помеченного конца рисуются скобки «( )» в редакторе, SVG IDEF0 и Visio; такая стрелка не считается нарушением баланса декомпозиции (`idef0_unbalanced`). **Слой подписей и номера** (лента студии, «Вид»; на диаграммах BPMN и IDEF0): «Подписи» скрывают названия событий и шлюзов под фигурами, условия стрелок BPMN и подписи стрелок IDEF0 (названия внутри задач и блоков остаются); «Номера» показывают код функции или шага на задачах BPMN и код на блоках IDEF0. Это настройка экрана (запоминается по сессии, в модель не пишется), PNG/SVG «как на экране» её учитывают, выгрузки сервера — нет. **Оформление фигур по видам** (раздел «Оформление» в свойствах выбранной фигуры, поле модели `shape_styles`, `shared/shapeStyles.ts`): заливка, цвет линии, цвет и размер текста для задач, подпроцессов, шлюзов, начальных, промежуточных и конечных событий BPMN и блоков функций IDEF0 — одно на все диаграммы, поэтому изменение у выбранной фигуры меняет все фигуры этого вида; значения, равные стандартным, не хранятся, «Сбросить к стандартному» возвращает вид. Применяется в редакторах, в PNG/SVG «как на экране» и в Visio (`.vsdx`); стрелки, серверные SVG и draw.io IDEF0, альбом и BPMN XML оформление не учитывают. **Наборы объектов** (раздел «Наборы» в навигаторе, поле модели `object_sets`): именованный список функций; в набор входит функция и всё вложенное в неё. Создаётся кнопкой «+» из выбранной функции, состав — в меню функции («В набор…», «Убрать из набора…»), название правится на месте. Щелчок по набору фильтрует дерево (члены набора и путь к ним, поиск тоже в рамках набора; фильтр запоминается), при активном наборе в ленте появляется выгрузка «BPMN набора (zip)» (`GET /api/sessions/:id/export/bpmn.zip?set=<id>`) и «Экспорт .xlsx» матрицы RACI по функциям набора (`GET /api/sessions/:id/raci/export/xlsx?set=<id>`). В набор можно включить и записи справочников (исполнители, системы, документы и данные, регламенты, показатели, риски): в таблице справочника у записи список «Набор»; при фильтре по набору справочник показывает только записи набора, матрица RACI — только функции набора. Регламент, должностные инструкции, паспорт и альбом строятся по процессу целиком и набором не ограничиваются. **Клавиши навигатора** (фокус в дереве, выбрана функция): Ctrl+C / Ctrl+X / Ctrl+V — копировать (вместе с вложенными функциями, шагами диаграмм BPMN, стрелками и ролями; название получает «(копия)» при совпадении), вырезать (при вставке переносится), вставить (внутрь выбранной, а если по Соглашению глубже операции нельзя — после неё; у процесса — на верхний уровень); F2 — переименовать на месте, Delete — удалить, Ctrl+↑ / Ctrl+↓ — переместить среди равных, Ctrl+F — в поиск; свёрнутые ветки и закрытые разделы запоминаются в браузере. **Переходы по диаграммам** (лента, «Модель»): «Предыдущая» и «Следующая» (Alt+←, Alt+→) по истории открытых диаграмм, «Вверх» — на диаграмму, где стоит функция текущей диаграммы (или операции для её BPMN), «Вниз» — в декомпозицию выбранной функции или в диаграмму BPMN её операции.
- **Вкладки-документы**: диаграммы BPMN и IDEF0 (встроенные редакторы с перетаскиванием, связями, дорожками, декомпозицией вглубь), справочники, отчёты.
- **Справочники**: исполнители (они же дорожки BPMN), информационные системы, документы и данные, регламенты и нормы, KPI, риски — добавление, правка, вид записи, «где используется» с переходом к шагу, удаление со снятием ссылок. Выбранная запись открывается карточкой в панели «Свойства».
- **Панель «Свойства»** справа — одна для всех документов. Показывает карточку выделенного объекта: шаг или функцию (общие атрибуты, исполнитель, сроки и стоимость, стороны блока IDEF0, RACI, источник в интервью, замечания проверки, история), стрелку потока, стрелку IDEF0 (с карточкой её документа или регламента) или запись справочника. Если ничего не выбрано — атрибуты процесса. Из карточки можно перейти к связанной записи и вернуться кнопкой «←».
- **Общий репозиторий объектов** (страница «Репозиторий», `server/src/objectRepo.ts`, `GET/POST /api/repository`): роли, информационные системы и документы хранятся один раз на всю организацию, запись справочника модели ссылается на объект полем `repo_id`. В студии: «Справочники → Из репозитория…» добавляет объект в модель, ⇪ у записи передаёт её в репозиторий (если такое название или синоним уже есть — запись связывается с существующим объектом, а не заводится дубль). На странице: синонимы, поиск по ним, «где используется» по всем процессам, **слияние дублей** (название исходного становится синонимом, записи моделей переходят на целевой объект) и **удаление только с заменой**, пока объект используется — оба действия в окне выбора с поиском, где объекты показаны с синонимами и использованием, а под списком написано, что именно произойдёт (Esc — закрыть, Enter или двойной щелчок — подтвердить). Правка названия, описания, ответственного и вида переносится в связанные модели (прежнее название остаётся синонимом; утверждённые версии не меняются, их число показывается). Класс «Регламенты и нормы», KPI, риски, подразделения, должности и пользовательские классы пока ведутся внутри модели.
- **Карточка записи справочника**: название, вид, описание, ответственный (у исполнителя — подразделение), реквизиты регламента, целевое значение и периодичность KPI, уровень и мера снижения риска; «где используется»; цитаты из интервью; история изменений по сохранённым версиям модели (`GET /api/sessions/:id/history/:kind/:entryId`). Описание и ответственный сохраняются при повторной обработке текста.
- **Отчёты**: паспорт процесса (атрибуты правятся на месте, печать), матрица RACI (с контролем «один A и хотя бы один R»), регламент и должностные инструкции (по сохранённой версии).
- **Проверки** снизу пересчитываются по ходу правки; щелчок по замечанию открывает нужную диаграмму. Рядом — открытые вопросы интервью. У замечаний с однозначным решением есть кнопка **«Исправить»** (код процесса по шаблону, лишний шлюз, петля IDEF0, граничное событие, исполнитель и владелец из списка, заготовка диаграммы операции, тупик потока, шлюз для разветвления и слияния и др.); **«Принять…»** признаёт предупреждение осознанным и записывает причину в модель (в счётчики оно не входит, виден список «принятые», агенты его не исправляют); замечания можно сгруппировать по правилам. Исправления и принятие — шаги общей истории (Ctrl+Z).
- Одна модель на все вкладки: общая история правок (Ctrl+Z / Ctrl+Y), одно сохранение (Ctrl+S), черновик переживает перезагрузку страницы.
- Выгрузка из ленты: BPMN 2.0 XML, IDEF0 SVG, VSDX, JSON модели (по сохранённой версии) и «Эта диаграмма» — SVG и PNG открытой диаграммы ровно как на экране, в том числе с несохранёнными правками.
- **Импорт из Visio** (`server/src/pipeline/vsdxImport.ts`; «Новая сессия» → режим В → «Microsoft Visio (.vsdx)», `POST /api/diagram-import/new` с `format: "vsdx"`, файл в base64): разбирается сам пакет OPC, без LLM. Шаги, события и шлюзы определяются по имени мастера («Task», «Decision», «Start Event», «Процесс», «Шлюз»…), а у фигур без мастера — по геометрии (эллипс, ромб, прямоугольник); подтип задачи — по имени мастера (user, service, manual…), триггер события — по нему же (сообщение, таймер…). Соединители берутся из приклеенных концов, неприклеенные привязываются к фигуре, в габарит которой попадают, стрелка на начале меняет направление, подпись соединителя становится условием ветки. Дорожки и пулы становятся исполнителями (шаг получает роль дорожки, в которой лежит; пул с вложенными дорожками роли не задаёт), события на краю задачи — граничными. Текст берётся и из фигур внутри групп. Несколько страниц — по операции на каждую (функция с названием страницы, шаги получают `bpmn_scope`), страницы IDEF0 пропускаются. Собственные выгрузки читаются обратно точнее — по меткам `pm_*`; на трёх эталонах (B002, C025, C090) шаги и стрелки возвращаются на 100%. Фигуры без текста — гипотезы; документы и хранилища данных не импортируются. Фигуры, нарисованные вручную без трафарета (Visio называет их `Sheet.5`), распознаются по форме: прямоугольник — шаг, ромб — шлюз, овал — событие. **Фигуры трафарета BPMN из Visio** читаются по свойствам (раздел Property, ячейки `Bpmn*`), а не по имени мастера: подтип задачи (пользовательская, сервисная, ручная, отправка, получение, сценарий, бизнес-правило), тип шлюза (исключающий, включающий, параллельный, событийный), вид события (начало, промежуточное, конец), его триггер и «выбрасывание», граничное событие без прерывания, ветка «по умолчанию». Свойства и размер фигуры по умолчанию берутся из мастера (экземпляр хранит только изменённое; словарь значений — `server/src/shared/visioBpmn.ts`, русские и английские названия). **Выгрузка пишет те же свойства**: у каждой BPMN-фигуры в «Данных фигуры» Visio — вид действия, тип задачи, тип шлюза, вид события и триггер, у стрелки — тип связи и условие (списки значений, как в трафарете «BPMN»; проверено открытием файла в Visio через COM). Параметры триггера (имя сообщения или ссылки, срок таймера, условие) лежат в метке `pm_trg`; если тип в «Данных фигуры» изменили, он сильнее метки, а при обратном импорте подтип, триггер и признаки возвращаются и у собственных выгрузок. Ассоциации и потоки сообщений пропускаются с предупреждением, цикличность задачи, сложный шлюз и неопознанные значения перечисляются в предупреждениях. Старый бинарный `.vsd` не поддерживается — его нужно пересохранить как `.vsdx`. Файл читается с пределами (одна часть пакета — 20 МБ после распаковки, весь файл — 60 МБ, 100 страниц, 6000 фигур на странице): «архив-бомба» отклоняется сразу.
- **Модель из таблицы Excel** (`server/src/pipeline/xlsxImport.ts`; «Новая сессия» → режим В → «Таблица Excel со списком шагов (.xlsx)», образец — `GET /api/diagram-import/template.xlsx` и ссылка «Скачать образец» в форме): одна строка — один шаг. Столбцы находятся по заголовку (русские и английские названия, порядок и лишние столбцы не важны, шапка может быть не в первой строке): `№`, `Название` (обязателен), `Тип` (задача, подпроцесс, решение, начало, конец, событие; для задачи — пользовательская, сервисная, ручная…), `Исполнитель` (становится дорожкой и записью справочника), `Следующий шаг` (номера или названия через «;», условие ветки в скобках: `5 (да); 2 (нет)`), `Система`, `Вход`, `Выход` (справочники «Информационные системы» и «Документы и данные», одна запись на название), `Срок`, `Комментарий`. Без столбца «Следующий шаг» шаги соединяются подряд (конец процесса ничего не продолжает). Выбирается лист, где распознано больше столбцов. Ссылка на шаг сначала ищется целиком (в названии могут быть скобки: «Оплатить (частично)»), и только потом разбирается как «шаг (условие)». Книга читается с теми же пределами, что и .vsdx. Строка без названия, неизвестная ссылка, повтор номера и нераспознанный столбец — предупреждения. Книга читается без библиотеки `xlsx` (в её разборе файлов есть уязвимости): .xlsx — ZIP с XML, его читают `jszip` и `fast-xml-parser`.
- **Работа с нуля**: режим «Г» при создании сессии даёт пустую модель без текста интервью и LLM (`POST /api/sessions/blank`); на пустой диаграмме есть подсказка.
- **Правка структуры в навигаторе**: функции перетаскиваются мышью (верх строки — перед, низ — после, середина — внутрь; подсказка показывает новый код «B002.01.02 → B002.01.01»), с проверкой Соглашения — подпроцесс делится на операции, глубже функций нет. После переноса коды пересчитываются, ссылки на них в поставщиках/потребителях продуктов и во внешних пулах обновляются, шаги диаграмм BPMN остаются у своих операций. Правый клик: добавить операцию/подфункцию, создать заготовку диаграммы BPMN, переместить вверх/вниз, дублировать, удалить (с подсчётом того, что исчезнет). Всё — шаги общей истории (Ctrl+Z). **Мастер структуры** (кнопка в ленте, меню процесса или пустое дерево): подпроцессы и операции списком с отступами, номера и коды в начале строк отбрасываются; справа предпросмотр с кодами и замечания (повторы названий, подпроцесс без операций, число блоков не 3–6); при желании у каждой операции создаётся заготовка диаграммы «начало → шаг → конец».
- **Несколько фигур на диаграмме BPMN**: Shift + рамка по пустому месту (с Ctrl — добавить к выделенному) или Shift + щелчок по фигурам; Ctrl+A — все. Группа переносится вместе (один шаг истории), сдвигается стрелками, удаляется Delete, дублируется Ctrl+D. Ctrl+C / Ctrl+X / Ctrl+V — копирование фрагмента: фигуры вместе с граничными событиями и стрелки между ними; буфер общий, поэтому фрагмент вставляется и в диаграмму другой операции (источники из интервью и подтверждения не копируются, должность остаётся, если такая дорожка есть). Панель внизу слева: копировать, вставить, приблизить к выделению, выровнять по левому краю / по линии (внутри дорожки) / равные промежутки, удалить. **Миникарта** (кнопка «Миникарта» в ленте): вся диаграмма уменьшенно, щелчок или перетаскивание по ней перемещает видимую часть.
- **Несколько блоков на диаграмме IDEF0**: те же приёмы — Shift + рамка или Shift + щелчок, Ctrl+A, перенос группой, стрелки, Delete, Ctrl+C / X / V / D. Скопированные блоки встают на открытый уровень (в том числе на другой) с названием «… (копия)» — названия функций уникальны; вложенные функции (декомпозиция) не копируются, стрелки-данные остаются. Панель: копировать, вставить, приблизить, выровнять влево / вверх, равные промежутки по горизонтали и вертикали, удалить. Миникарта — кнопка «Миникарта» в ленте.
- **Стрелки и шлюзы BPMN**: все стрелки диаграммы прокладываются вместе (`server/src/shared/bpmnRouting.ts`) — этим же кодом пользуются редактор, выгрузка BPMN/VSDX и альбом, поэтому линии на экране и в файле совпадают. Для каждой стрелки перебираются пары «сторона выхода × сторона входа» с шаблонами ломаной (прямая, Г-, Z- и П-образная); цена пары — изломы, длина, проход сквозь фигуры и значки документов, пересечения с другими стрелками, наложение на их неподвижные участки и занятость порта. Правила: **из одного порта выходит одна стрелка и в один порт входит одна** — у ромба и круга порт одноразовый (ветки шлюза уходят из правой, верхней и нижней вершины, слияние входит в левую, верхнюю и нижнюю), у задачи на одной стороне стрелки получают разные точки; потоки сообщений и стрелки к пулам идут тем же механизмом; **линии не накладываются**: средние участки Z- и П-образных стрелок разводятся каналами с шагом 10 px, а «крест-накрест» между двумя уровнями — разными формами. Граничное событие ведёт линию вниз; возврат назад — петля, у событий и шлюзов (подпись снизу) — поверху. Условие ветки подписывается за поворотом. На эталонах B002, C025 и демо (326 стрелок на 20 диаграммах) — ни общих портов, ни наложений, ни проходов сквозь фигуры; это проверяют тесты. Фигуры привязываются к сетке по центру (шаг 5 px), поэтому события, шлюзы и задачи одного ряда лежат на одной линии; ранее расставленные диаграммы выравнивает кнопка «Авто-раскладка». **Правило портов строгое для любых фигур: в один вход входит одна стрелка, из одного выхода выходит одна** (у ромба и круга — по вершинам, у задачи — по сторонам; точки на одной стороне делятся только когда свободных сторон не осталось). Пересечения путей стрелок штрафуются сильнее любого обхода, поэтому они остаются только там, где иначе нельзя (в основном когда так расположены сами фигуры); `Авто-раскладка` расставляет фигуры заново.
- **События и триггеры BPMN**: у события два независимых признака. **Вид** — начальное, промежуточное, конечное; граничное — событие, прикреплённое к задаче. **Триггер** — что событие запускает или выбрасывает: сообщение, таймер, условие, сигнал, ошибка, эскалация, компенсация, отмена, ссылка, завершение процесса, несколько (любой из / все сразу). Допустимые триггеры зависят от вида по BPMN 2.0 (например, у начального нет ошибки, у конечного нет таймера; промежуточное «ждёт» или «выбрасывает» — значок не залит или залит). Параметры триггера: таймер — дата, срок (P3D, PT2H) или период (R/P1W); условие — текст; сообщение, сигнал, ошибка, эскалация, ссылка — название. Задаётся в карточке «Событие и триггер», палитра «События с триггером» создаёт заготовки (начало по сообщению, ждать таймер, отправить сообщение, конец с ошибкой…), у задачи — граничные события с любым триггером. Проверки: триггер не подходит виду (ошибка), у граничного события нет триггера, не заполнены параметры, ссылка без пары; для недопустимого триггера есть быстрое исправление со списком допустимых. В BPMN-файл попадают определения триггеров с параметрами (	imerEventDefinition с 	imeDuration, messageEventDefinition со ссылкой на объявленное сообщение и т. д.), в Camunda-экспорт и VSDX — те же значки и определения; импорт .bpmn восстанавливает триггеры, направление и граничные события. Прежняя запись, где в subtype лежал 	imer/message/error/signal, читается как промежуточное событие с этим триггером и продолжает работать.
- **Цикличность задачи и ветка по умолчанию BPMN.** У задачи и подпроцесса поле `loop`: `standard` (повторять), `parallel` или `sequential` (несколько экземпляров) — маркер на фигуре (круговая стрелка, три вертикальные или горизонтальные черты), выбирается в свойствах шага («Цикличность (BPMN)»). У стрелки из задачи, подпроцесса, исключающего или включающего шлюза поле `is_default` — ветка по умолчанию (одна на узел; косая черта у начала стрелки, флажок в свойствах стрелки). В BPMN XML и в экспорте Camunda это `standardLoopCharacteristics`, `multiInstanceLoopCharacteristics isSequential=…` и атрибут `default` источника; в VSDX — `BpmnLoopType`, `BpmnConditionType = По умолчанию` и маркер на фигуре. Импорт `.bpmn` и `.vsdx` восстанавливает оба признака.
- **Утверждённая версия в студии — только чтение.** Если статус процесса «Утверждён», студия показывает баннер «Версия утверждена и заблокирована от изменений» с кнопкой «Открыть новый цикл правок» (тот же `reopen`, что в разделе согласования); перетаскивание и правка в диаграммах, поля свойств, перенос и удаление в навигаторе, отмена и повтор отключены, сохранить нельзя. Раньше правка доходила до сохранения и отклонялась сервером (409).
- **Триггеры блока.** Ожидающий триггер (сообщение, таймер, условие, сигнал), который ведёт прямо в задачу или подпроцесс, на диаграмме — **значок на блоке**: отдельной фигуры события и стрелки «событие → блок» нет (стрелка «X → событие» идёт к самому блоку). Значок стоит на левом крае и верхней границе блока; щелчок по нему открывает свойства триггера. Добавляется кнопкой «+ Сообщение / Таймер / Условие / Сигнал» в разделе «Триггеры блока» карточки блока или заготовкой из палитры при выбранном блоке; удаляется крестиком в карточке или клавишей Delete на значке — вход блока при этом сохраняется. В модели и в файле BPMN остаются настоящее событие и стрелка (файл валиден), а редактор, раскладка и выгрузка в Visio работают со «свёрнутым» видом; граничные события и события-ссылки остаются фигурами.
- **Размер дорожек: высота и ширина.** У каждой дорожки своя высота (120–600 px, по умолчанию 150, шаг 10). Тяните нижнюю границу дорожки на диаграмме (пунктирная линия показывает, где она встанет; Alt — без привязки к шагу) или выберите дорожку за её подпись и введите высоту в панели над диаграммой («Стандартная» возвращает 150, «Всем дорожкам» делает все такой же высоты). Дорожки ниже едут целиком, фигуры дорожки, стоявшие по её центру, остаются по центру, а поставленные вручную в другом месте — на месте; ниже, чем нужно фигурам дорожки (с граничными событиями), её сделать нельзя. Высота хранится у роли (lane_height, одна на все диаграммы, где эта роль есть), у дорожки «Без исполнителя» — в настройках процесса (process.unassigned_lane_height); попадает в раскладку, BPMN DI, Visio и альбом. Ширина дорожек (правый край) растягивается в сторону: тяните правую границу дорожек мышью или введите «Ширина дорожек» в той же панели («По содержимому» снимает настройку). Ширина хранится для каждой диаграммы отдельно (diagram_widths: ключ — id операции, пустая строка — общая схема процесса), это нижняя граница: уже, чем нужно фигурам и внешним пулам, дорожки не делаются, а шире — оставляют место для новых фигур; попадает в BPMN DI, Visio и PNG/SVG «как на экране». Документы и хранилища данных над и под задачей рассчитаны на стандартную высоту: в дорожке ниже 150 px им может не хватить места.
- **Правка стрелок вручную — свободная.** Выберите стрелку: на ней появятся ручки. Круглые ● на концах переносят конец на другую сторону той же фигуры, на другую фигуру (с теми же проверками, что при создании связи; у стрелки к блоку с триггером — только сторона) или вдоль стороны (положение запоминается). Ручка ▮ посреди отрезка сдвигает отрезок поперёк (у порта линия сама делает короткий прямой участок и ступеньку, Alt — без привязки к сетке 5 px), квадрат ■ на изломе переносит излом вместе с двумя его отрезками. Ctrl + двойной щелчок по стрелке (или кнопка «Добавить излом») делает ступеньку — два новых излома, которые затем тянут куда нужно; двойной щелчок по излому убирает его (ступенька убирается целиком). Пока отрезок, излом или конец стрелки перетаскивают, на экране появляются направляющие — розовые ровные линии по горизонтали или вертикали, когда перетаскиваемое совпадает с верхом, серединой или низом (левым краем, серединой, правым краем) любой фигуры, с портом стрелки, с другим её изломом или с изломом любой другой стрелки; то же при перетаскивании фигуры и группы: левый край, середина и правый край (верх, середина, низ) выравниваются с такими же линиями остальных фигур, а середина — ещё и с центром дорожки, при отпускании выровненное положение остаётся точным (по другой оси фигура по-прежнему ложится на сетку); элемент к такой линии прилипает (допуск 6 px экрана, Alt — без направляющих и без сетки), а конец стрелки вдоль стороны выравнивается по другому концу — тогда стрелка идёт прямо. Остальные стрелки обходят ручную. Маршрут хранится в стрелке (`route`: стороны выхода и входа, `from_pos`/`to_pos` — положение концов на сторонах, `points` — точки излома, `channel` — положение среднего участка у прежних маршрутов), попадает в экспорт BPMN, Visio и PNG/SVG «как на экране» и переживает перезагрузку; линия всегда ортогональна, недостающие колена достраиваются (`shared/bpmnManual.ts`). Первая же правка делает маршрут ручным, «Сбросить маршрут» возвращает автоматическую прокладку (кнопка на панели над диаграммой и в карточке стрелки, где стороны, положения концов и точки можно задать и списком). Если заданные стороны не подходят после перемещения фигур, стрелка прокладывается автоматически.
- **Двойной щелчок правит текст того, по чему попали.** BPMN: фигура (задача, событие, шлюз) — её название; значок-триггер на блоке — название триггера; стрелка — условие ветки (пустое значение стирает условие). IDEF0: функция — название; стрелка — название её документа, регламента, системы или исполнителя (запись справочника одна, поэтому подпись меняется у всех её стрелок). Ручка отрезка выбранной стрелки считается частью линии. Излом на стрелке добавляется по **Ctrl + двойной щелчок** (или кнопкой «Добавить излом»), двойной щелчок по излому его убирает. По пустому месту диаграммы обычный двойной щелчок ничего не делает, чтобы не создавать лишнего; новая функция IDEF0 — **Ctrl + двойной щелчок** или перетаскивание «Функции» из палитры (в BPMN — из палитры). Esc отменяет правку.
- **Документы, хранилища данных и внешние пулы BPMN — полноценные объекты.** Щелчок по значку документа (или хранилища) выбирает запись справочника и открывает её карточку, двойной щелчок переименовывает её на месте (название общее для модели), значок можно перетащить (смещение хранится у задачи в `artifact_offsets`, ассоциация перестраивается, значок может стоять и сбоку; «Вернуть на место» — в панели выбранного значка). Подписи соседних значков не налезают друг на друга: расстояние считается по ширине подписей. Внешний пул — выбирается щелчком (карточка пула и потока в «Свойствах»), переименовывается двойным щелчком, двигается мышью (`dx`/`dy` в пуле), удаляется клавишей Delete; кнопка палитры **«Внешний пул»** создаёт самостоятельный пул (виден на диаграмме, где создан), инструмент **«Поток сообщений»** рисует стрелку «шаг → пул» или «пул → шаг» двумя щелчками (или протянуть ● выбранного шага на пул). Поток сообщений — отдельная стрелка со своим маршрутом: ручки отрезков и изломов, «Добавить излом», «Сбросить маршрут» (`route` в потоке); учитывается в экспорте BPMN.
- **Рамка листа IDEF0** (`server/src/shared/idef0Frame.ts`): клетчатое поле, контур и штамп `NODE / TITLE / NO.` — в редакторе, в SVG-выгрузке, draw.io и VSDX. Каждая надпись штампа (и подписи, и значения) правится двойным щелчком, пустое значение возвращает автоматическую. Лист растягивается за любой край и угол, двигается за штамп (шаг клетки 20 px), в меню **«Лист»** — рамка и сетка, форматы A4 / A3 / A2, поворот, «Авторазмер»; предупреждение «Вне листа: N» показывает функции за границей заданного вручную листа. **Печать листа:** в ленте студии на диаграмме IDEF0 — «Лист в PDF» и «Печать…» (выбор бумаги A4 / A3 / A2, по умолчанию — по формату рамки); `GET /api/sessions/:id/export/idef0/<decomposition | context | код функции>.pdf` и `.print.html` (`?paper=A4|A3|A2&orientation=landscape|portrait`). Лист строится из актуальной модели (без «Пересобрать диаграммы») и вписывается в страницу без полей с сохранением пропорций. PDF делает Chromium (Playwright), на рабочем месте — установленные Edge или Chrome; без браузера отдаётся подсказка про страницу печати. Настройки — по диаграммам в `model.idef0_frames` (ключ: id функции, пустая строка — верхняя диаграмма, `ctx` — контекстная).
- **Рамка листа BPMN** (`editor-core/sheetFrame.tsx`, `sheet-ops.ts`): то же меню «Лист» в редакторе BPMN, но рамка **по умолчанию выключена** — включается кнопкой «Рамка» для нужной диаграммы. Автоматический лист накрывает дорожки целиком с полем 40 px справа (края листа не совпадают с ручкой ширины дорожек); штамп по умолчанию — код и название операции (у общей схемы — процесса), правится двойным щелчком; лист растягивается, двигается за штамп, отмечаются фигуры вне листа, «Вписать» показывает лист со штампом. Настройки — в `model.bpmn_frames` (ключ: id операции, пустая строка — общая схема процесса). PNG/SVG «как на экране» включают рамку. **Печать листа BPMN** (лента на диаграмме BPMN, бумага A4 / A3 / A2, по умолчанию — по формату листа или A4 по пропорциям): «Печать…» открывает страницу печати в новой вкладке, «Лист в PDF» — `POST /api/sessions/:id/export/sheet.pdf` с `{ svg, title, paper, orientation }`. Рисунок берётся с экрана (в том числе с несохранёнными правками): серверной отрисовки, совпадающей с редактором, у BPMN нет; включённый лист печатается по рамке, без рамки — вся диаграмма. Сервер очищает присланный SVG (без сценариев, обработчиков, HTML-вставок, внешних ссылок), а браузер для PDF работает без JavaScript и без сети. Страница печати общая с IDEF0 — `shared/sheetPrint.ts`. **В Visio (`.vsdx`)** включённый лист BPMN выгружается, как у IDEF0: контур и штамп с надписями (без сетки) под диаграммой; автоматический лист накрывает пул выгрузки с тем же полем, заданный вручную стоит по своим координатам и при необходимости увеличивает страницу (лист в отрицательных координатах не выгружается). Лист — оформление: при чтении правок из Visio он пропускается. В `.bpmn` и альбоме листа нет: в BPMN XML для него нет элемента, а альбом рисует упрощённую схему.
- **Настольное приложение с Visio в редакторе** (`desktop/ProcessStudio`, Windows, .NET 8, нужен установленный Visio 2016+ x64): окно, в котором студия работает в WebView2, а **на месте холста диаграммы — настоящий Visio** (компонент «Microsoft Visio 16.0 Drawing Control»). Навигатор, лента, свойства, проверки и справочники остаются студией. В настольном режиме (`web/src/desktop.ts`) студия вместо холста BPMN и IDEF0 показывает пустое место (`VisioSlot`) и сообщает оболочке его положение и открытую диаграмму; оболочка кладёт на это место окно Visio, выгружает `.vsdx` всей сессии (один раз, пока модель не изменилась) и переключает страницу по меткам `pm_page` / `pm_scope` / `pm_parent` (контекстная страница IDEF0 — `pm_ctx`). Вкладки студии переживают перезагрузку. Кнопка **«Принять из Visio»** (лента, «Файл») сохраняет документ и отправляет его на `POST /api/sessions/:id/diagram-import/vsdx`: переименованные шаги и условия стрелок, новые шаги (на странице своей операции, исполнитель — по дорожке) и новые стрелки попадают в модель; удалённое в Visio только перечисляется. Если модель изменили в студии, а в Visio есть непринятые правки, оболочка не перезаписывает Visio и просит сначала принять правки. **Палитра и живая связь:** слева от диаграммы BPMN — палитра фигур (задача, подпроцесс, три события, два шлюза): фигуру тянут на диаграмму или щёлкают; фигура рисуется примитивами Visio в цветах и размерах выгрузки и после приёма правок становится шагом модели (фигуры из мастеров документа подвешивают сохранение в окне Visio, поэтому не используются; `SaveAs` в окне Visio зацикливается на изменённой показанной странице, пока окно видно, — оболочка прячет окно на время сохранения). Новые фигуры помечаются id созданных шагов и потоков (`pm_k`, `pm_id`, `pm_manifest`), поэтому повторный приём правок дубликатов не создаёт. Выделенная в Visio фигура открывается в панели свойств студии, шаг, выбранный в студии, выделяется в Visio; правки принимаются сами, когда пользователь перешёл к другой фигуре (мышь отпущена) или после 5 с тишины, студия получает обновлённую сессию без перезагрузки. Удалённое в Visio только перечисляется (в модели остаётся). Сервер запускается вместе с окном и сам отдаёт собранный интерфейс (`WEB_DIST` — `web/dist`, нужен `npm run build`); данные — в `server/data` или в каталоге из `--data`. Сборка: `dotnet build desktop/ProcessStudio -c Release` (если .NET поставлен в профиль пользователя — `DOTNET_ROOT=%LOCALAPPDATA%\dotnet`). Самопроверка без участия пользователя: `ProcessStudio.exe --selftest <папка>` (временная база, демо-процесс, Visio на месте холста, переключение вкладок, правка в Visio и возврат в модель, снимки в папке). Веб-версия работает как раньше и от Visio не зависит. `desktop/VisioSpike` — исходная проба встраивания.
- **Общий репозиторий объектов:** если запись роли, системы или документа изменена в процессе, карточка показывает отличия от объекта репозитория; «Обновить объект в репозитории» переносит правку в другие процессы (кроме утверждённых версий и открытой сессии), «Взять из репозитория» возвращает значения объекта. В ленте студии есть кнопка **«Импорт…»** — приём правок из внешних редакторов; новую модель из Visio, Excel или изображения создают на странице «Новая сессия».
- **Правка стрелок IDEF0 вручную.** Выберите стрелку на диаграмме: появятся ручки (размер постоянный на экране при любом масштабе). **○ конец у блока** — тяните вдоль стороны блока, и конец сдвинется (положение хранится долей стороны, 5–95%); отпустите над другой функцией — стрелка *переносится*: меняется связь в модели (вход, управление, выход, регламент или система переходят к другой функции; у связи «выход → вход» так же переносится источник — отдельной ручкой). Над верхней частью блока документ становится управлением, над остальным — входом; та же смена типа — кнопка «Сделать управлением / входом» и список «Тип стрелки» в свойствах. **◇ свободный конец** внешней стрелки (вход, управление, механизм, выход) — в любую точку, не ближе 48 px к блоку по направлению стрелки. **▭ отрезок** сдвигается поперёк, **■ излом** — куда угодно (Ctrl + двойной щелчок по линии добавляет ступеньку, двойной щелчок по излому убирает его), **подпись** — за ромбик над ней. К сетке 10 px и направляющим (границы и середины блоков, вершины своей и других стрелок) прилипает, Alt — без привязки. Всё — шаги общей истории (Ctrl+Z). «Сбросить маршрут» (панель над диаграммой и свойства стрелки) возвращает автоматическую прокладку. Маршрут хранится у функции стрелки (`arrow_routes`, ключ «вид:сущность»: `input:d1`, `link:d2`, `control:c1`, `system:s1`; поля `pos`, `from_pos`, `points`, `end`, `label`) и применяется общей раскладкой (`shared/idef0Layout.ts`) — поэтому SVG (после «Пересобрать диаграммы»), VSDX и draw.io совпадают с редактором. При переносе блока (мышью, стрелками клавиатуры, группой, выравниванием) свободные концы и изломы его внешних стрелок едут вместе с ним, а изломы связи с другой функцией остаются (при переносе группы они едут, если источник тоже в группе); у копии (Ctrl+C/V, Ctrl+D) внешние стрелки едут с копией, а связи с другими функциями получают автоматический маршрут. Перенос конца или разрыв связи сбрасывает маршрут стрелки; роль-механизм переносится не ручкой, а в свойствах функции.
- **Удобство работы**: «На весь экран» для окна студии, масштаб 100%, дублирование функции или шага (кнопка «Дублировать» или Ctrl+D), сдвиг выбранной фигуры стрелками (Shift — крупнее), поиск по функциям и записям справочников в навигаторе.
### Структура модели по Соглашению о моделировании

- **Код процесса** (паспорт, например `B002.00.00`) включает структуру по Соглашению: функции верхнего уровня — подпроцессы `B002.01.00`, их дочерние — операции `B002.01.01`, шаги диаграммы BPMN операции — подоперации `B002.01.01/001`. Без кода процесса нумерация прежняя (A1, A21…), новые правила проверки не применяются. Коды выводятся из порядка функций, пропусков не бывает.
- **Диаграмма BPMN у каждой операции**: кнопка ⬡ в навигаторе или «Диаграмма BPMN операции» в свойствах. Шаги операции хранятся в той же модели (`bpmn_scope` = id операции) и не попадают в IDEF0 и общую схему процесса; дорожки выводятся из исполнителей. Выгрузка: `GET /api/sessions/:id/export/bpmn?scope=<id операции>`, `export/bpmn.zip` (файл на операцию), страницы `BPMN <код>` в VSDX.
- **Ролевая модель**: должности (с квалификацией) в ролях владелец / исполнитель / соисполнитель / контролёр / наблюдатель с функциями; на процесс в целом и на каждую функцию. В IDEF0 роли показываются механизмами (несколько на блок). Проверки: у процесса/подпроцесса один владелец, у операции есть исполнитель.
- **Карточка продукта** (справочник «Документы и данные»): поставщик и потребитель (выводятся из связей функций или задаются внешние), ценность для потребителя, стандарт качества. Отчёт «Схема перехода статусов» строится автоматически по связям «выход → вход/управление».
- Проверки структуры: формат кода процесса, глубина (процесс → подпроцесс → операция), у подпроцесса есть операции, у операции есть BPMN.
- **Элементы BPMN из Соглашения**: задача «Бизнес-правила»; граничные события (таймер, сообщение, ошибка, сигнал; прерывающие и нет) — кнопка «Гр. событие» в палитре или раздел «Граничные события» у задачи, стоят на нижней границе задачи; документы (входы/выходы) и хранилища данных (информационные системы) — значки под задачей с ассоциациями (правее граничных событий, в обход потока сообщений); внешние пулы других процессов (по коду) и потоки сообщений — раздел «Потоки сообщений» у шага и «Внешние пулы» в свойствах процесса. Всё это попадает в BPMN XML, VSDX и SVG/PNG.
- **Процесс C025** «Организация обучения и аттестации персонала» по документу «ДПО от 05.10»: A-0, A0, декомпозиция C025.01.00 и BPMN пяти операций (дорожка ELMA365, три согласования, свёрнутый пул «Поиск программы и внесение в список»). Загрузка: `npm run seed:c025 -w server`; эталон B002 — `npm run seed:b002 -w server`. Проверки Соглашения показывают настоящие пробелы документа (развилки не после задачи, A0 из двух блоков, не названы владелец и внешние поставщики и потребители); отступления модели от документа перечислены в заголовке `server/src/reference/c025.ts`. Атлас Visio (VSDX) идёт в порядке документа: A-0 → A0 → диаграмма подпроцесса и BPMN его операций → … → общая схема.
- **Демонстрационный процесс C090** «Закупка и ввод в эксплуатацию оборудования» (`npm run seed:demo -w server`) — витрина всех возможностей на одном процессе: коды и группа в навигаторе, три подпроцесса и шесть операций с диаграммами BPMN, полная ролевая модель (владельцы, исполнители, соисполнители, контролёры, наблюдатели, квалификации), продукты с внешними поставщиками и потребителями, все семь видов задач, шлюзы XOR/AND/OR/по событию, свёрнутые подпроцессы и внешние пулы, граничные события (таймер с прерыванием и без, ошибка, компенсация), все триггеры событий, кроме отмены (сообщение, таймер с датой, сроком и периодом, условие, сигнал, ошибка, эскалация, компенсация, пара ссылок, терминатор, «несколько» и «несколько сразу»), возвраты на доработку, обходы и ветки вверх и вниз. Проверки молчат; одно осознанное отступление (развилка после события) принято с причиной. Это не реальный процесс, а образец для обучения и проверки редактора.
- **Проверки по правилам Соглашения** (при структурном коде процесса): событие сформулировано как факт; перед развилкой XOR стоит задача; поток не разветвляется и не сливается без шлюза; граничные события (вход, продолжение, задача); концы потоков сообщений (отправка/получение); одинаковые названия блоков и петли IDEF0; входы без источника и выходы без назначения; коды в полях «поставщик/потребитель» — существующая функция, которая действительно выпускает или использует продукт.

## Агенты (Cline)

Модель процесса можно строить и править агентами Cline (главный агент и субагенты). Приложение не вызывает для этого LLM: Cline работает
со своей моделью в VS Code и общается с приложением через MCP-сервер (`npm run mcp -w server`, `server/src/mcp`).

- **Агент только предлагает — применяет человек.** Агент читает модель и замечания проверок и отправляет предложение — список операций
  (добавить, изменить, удалить, назначить роли). Предложение проверяется до сохранения: ссылки, повторы id, соответствие схеме. В студии вкладка
  «Предложения агентов» показывает правки по-русски и их влияние на проверки; «Применить» кладёт их в черновик (можно отменить), «Отклонить…» — с причиной,
  которую агент увидит.
- **Доступ агента** — токен `AGENT_API_TOKEN`, только ручки `/api/agent/*` (чтение, предложения). Решать по предложениям и править модель напрямую он не может.
- **Правила для агентов** — `.clinerules/` и `GET /api/agent/conventions` (структура Соглашения, названия, BPMN, роли, продукты, формат правок).
- **Задания аналитика**: вкладка «Задания агенту» — поручение агенту («разбей операцию на шаги»), он забирает его через MCP и отвечает предложениями; цитаты в источниках проверяются по тексту интервью.
- **Эталон B002** (`server/src/reference/b002.ts`) и сравнение с ним (`npm run eval:b002 -w server`), проверка связи (`npm run agent:check -w server`), имитатор агента (`npm run agent:demo -w server`).
- **Вопросы и отчёты агентов**: вкладка «Вопросы» — вопросы к следующему интервью от интервьюера (адресат, функция, приоритет; отметки «задан», «получен ответ», «снят»; лист для интервью одной кнопкой; в чате интервью кнопка «Свой вопрос» — интервьюер задаёт владельцу собственный вопрос, а ответ отмечает его полученным); вкладка «Отчёты» — выводы аналитика структурой и полным текстом, архив. Вкладка «Агенты» — статистика по ролям (принято и отклонено, причины отказа, подсказки по инструкциям); конфиденциальную сессию агенты видят, только если аналитик разрешил доступ; `npm run agent:config -w server` печатает готовый конфиг Cline. Лист вопросов и каждый отчёт выгружаются в Word; отчёт помечается, если модель с тех пор изменилась; о новых предложениях, вопросах и отчётах приходят уведомления. Модель они не меняют.
- Подключение, инструменты, роли и формат предложения — [docs/agents/README.md](docs/agents/README.md).
## Тесты и CI

```bash
npm test             # сервер (vitest) + клиент (vitest + jsdom): логика модели, компоненты студии, окно студии целиком
npm run test:e2e     # сквозные сценарии в браузере (Playwright): вход, BPMN, IDEF0, карточки, черновик, конфликт версий
npm run test:coverage -w web   # покрытие клиентского кода
npm run typecheck    # TypeScript сервера и клиента
npm run fuzz -w server   # фаззинг (~1,5 мин): все ручки API случайными и неверными по типу телами + странные модели во всех выгрузках
```

- **Сервер** — ядро (IDEF0, BPMN, валидация, VSDX), конвейер, вход, задачи, хранилище, история записей; временная база (`DATA_DIR`) и офлайн-провайдер.
- **Клиент** (`web/src/**/*.test.ts(x)`) — операции над моделью и справочниками, геометрия, маршрутизация, транспорт API, история правок и черновик, панель свойств, карточки, справочники, RACI, паспорт, навигатор, проверки и интеграционный тест окна студии.
- **Фаззеры** (`server/test/*.fuzz.ts`, отдельный конфиг) — ищут ответы 500, падения процесса и медленные ответы; ожидают ноль находок. Ошибки асинхронных обработчиков перехватываются общим слоем и не роняют сервер; ошибки ввода отдаются как 400/413.
- **Золотые снимки раскладки** (`server/test/layoutGolden.test.ts`, `web/src/components/bpmn-editor/layoutGolden.test.ts`, файлы в `__golden__`): координаты блоков, ломаных стрелок, подписей, значков и пулов эталонов B002, C025 и демо — IDEF0, BPMN сервера и то, что рисует редактор (плюс модель с правками вручную). Любое непреднамеренное смещение видно в diff; намеренное изменение раскладки — `npx vitest run <файл> -u` и просмотр diff снимков перед коммитом. Картинки не сравниваются: они зависят от шрифтов машины, а координаты — нет.
- **Обход интерфейса** (`web/e2e/smoke.e2e.test.ts`) — открывает все вкладки сессии и страницы приложения, щёлкает по объектам студии и следит за ошибками консоли и срабатыванием страховки ErrorBoundary.
- **Сквозные** (`web/e2e`) — поднимают свой API (порт 18787, временная база, вход `e2e`, без ключей LLM) и Vite (15173), не мешая dev-серверам. Браузер: на Windows — установленный Edge, иначе Chromium из Playwright (`E2E_BROWSER_CHANNEL`, `E2E_HEADED=1` — с окном).

CI (`.github/workflows/ci.yml`): typecheck, тесты сервера и клиента, сборка клиента; отдельной задачей — сквозные тесты в Chromium.

## Эксплуатация

| Переменная | Назначение |
|---|---|
| `AUTH_USERS`, `HOST`, `CORS_ORIGIN` | вход, адрес прослушивания, разрешённые источники |
| `DATA_DIR` | каталог базы и рабочих файлов (по умолчанию `server/data`) |
| `LLM_TIMEOUT_MS`, `LLM_RETRIES` | таймаут одного вызова LLM (120 000) и число повторов (3) |
| `AGENT_MAX_ITERATIONS` | повторные проходы оркестратора (для платных LLM по умолчанию 1) |
| `LLM_PRICE_INPUT_PER_M`, `LLM_PRICE_OUTPUT_PER_M` | цены за 1 млн токенов — для оценки стоимости в «Журнале агентов» |
| `BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP` | резервные копии SQLite в `data/backups` (24 ч, 7 копий; 0 — выключить); каждая копия проверяется `integrity_check` |
| `BACKUP_COPY_DIR` | вторая копия вне диска данных (сетевая папка, облачный каталог); без неё копии лежат только рядом с базой |

**Копии вручную и восстановление.** `npm run backup -w server` — копия базы сейчас (с проверкой); `-- --repo` — ещё и весь git-репозиторий одним файлом `repo-….bundle` (код приложения; у репозитория нет удалённого, и bundle — копия на случай потери машины; в `BACKUP_COPY_DIR`, а если она не задана, в `data/backups`). Код из bundle: `git clone repo-….bundle <папка>`. База из копии: остановить сервер, `npm run restore -w server -- data/backups/app-….sqlite --yes` — копия проверяется, прежняя база сохраняется рядом (`app-before-restore-…`), так что восстановление можно отменить.

Расход токенов по сессии: `GET /api/sessions/:id/llm-usage` и вкладка «Документы и выгрузка → Журнал агентов».

## Покрытие функциональных требований

| Раздел ТЗ | Реализация |
|---|---|
| ФТ-1 Предобработка | `pipeline/fragment.ts` — фрагментация, определение спикера, нормализация по словарю (`/api/glossary`), обезличивание ФИО |
| ФТ-2 Интерактивное интервью | `pipeline/interviewEngine.ts` + `routes/interview.ts` — сценарий, приоритизация вопросов, живое превью BPMN, отметка неверных элементов, ограничитель повторов, протокол |
| ФТ-3 Извлечение структуры | `pipeline/extract.ts` + `llm/*` — structured output, проверка ответа, цитаты, уверенность, статус «гипотеза», классификация AS-IS/TO-BE/проблема. **Структура:** LLM возвращает операции (`operations`), принадлежность действия операции (`operation_name`) и — при глубине декомпозиции 2 — подпроцессы (`subprocesses` + `subprocess_name` у операции): операции становятся блоками IDEF0 (при глубине 2 — детьми подпроцесса), их действия получают `bpmn_scope` и образуют диаграмму операции, а связи между действиями разных операций переносятся на общую схему (дедуплицируются и заменяются связью «операция → операция»). Мастер структуры открывается с готовым списком из модели (`outlineFromModel`) — аналитик правит его, а не набирает с нуля |
| ФТ-4 Пробелы и противоречия | `pipeline/gaps.ts` — правила полноты, противоречия исполнителей, неявные ветвления, приоритеты, лист вопросов |
| ФТ-5 Валидация | `pipeline/validate.ts` — старт/конец, недостижимые узлы, тупики, поведение BPMN перебором состояний (`shared/soundness.ts`: блокировки на шлюзах — ошибка, конечное событие, не останавливающее параллельные ветки, цикл без выхода и слияние параллельных веток без шлюза AND — предупреждения), число блоков IDEF0, баланс декомпозиции, управление/выход, стиль наименований |
| ФТ-6 Генерация BPMN | `pipeline/bpmn.ts` + `pipeline/layout.ts` — пул/дорожки, типы задач/событий/шлюзов, объекты данных, раскладка: два исходных варианта (ELK и по столбцам — shared/bpmnRank.ts, один алгоритм с кнопкой «Расставить» в редакторе) и подбор порядка и столбца фигур по числу пересечений стрелок (дорожки прежние; на эталонах B002, C025 и демо пересечений 43 → 7; ходы подбора: порядок фигур слоя, сдвиг на слой, перестановка двух фигур дорожки, вставка фигуры на другое место дорожки и перенос запутанной фигуры в любой столбец, если стрелки вперёд остаются вперёд (последние три — на диаграммах до 40 стрелок); подбор оценивает ту же прокладку, что получится в итоге, — вместе с потоками сообщений к внешним пулам; подписи событий и шлюзов стрелки обходят (shared/bpmnLabels.ts), налезание подписей друг на друга штрафуется; LAYOUT_SEARCH=0 выключает подбор); при прокладке стрелок стороны выхода и входа пересматриваются парами у пересекающихся стрелок с общим концом (`shared/bpmnRouting.ts`), позиции из редактора |
| ФТ-7 Генерация IDEF0 | `pipeline/idef0.ts` + `shared/idef0Layout.ts` — A-0, A0, декомпозиция вглубь (A21…), ICOM-стрелки, выход как управление, узловое дерево, draw.io |
| ФТ-8 Согласованность нотаций | Обе нотации строятся из одной модели; правка модели помечает диаграммы «к пересборке» (`diagramsStale`); повторная обработка текста сохраняет ручные правки |
| ФТ-9 Редактор и трассировка | Студия: редакторы BPMN и IDEF0 (undo/redo, черновики), справочники, паспорт, RACI, клик по элементу → подсветка цитаты, версии и diff, комментарии, защита от одновременных правок |
| ФТ-10 Экспорт | `.bpmn`, IDEF0 `.svg`/`.drawio`, Visio `.vsdx`, JSON модели, лист вопросов, протокол, проблемы/предложения TO-BE, HTML/PDF-альбом |
| ФТ-11 Шаблоны и справочники | `/api/templates` (сценарии интервью), `/api/glossary` (словарь терминов/ролей) |

## Известные ограничения

- **Офлайн-экстрактор** — эвристика на правилах; для заявленного качества извлечения нужен LLM-провайдер. Операции
  (`operations`) он не строит: модель из офлайн-режима остаётся плоской, операции собирают в мастере структуры вручную.
- **Корпоративная сеть подменяет TLS:** сервер падает с `LLM не обработал ни одного фрагмента: fetch failed`
  (`SELF_SIGNED_CERT_IN_CHAIN`) — Node не читает хранилище сертификатов Windows. Лечится `NODE_EXTRA_CA_CERTS` с PEM-файлом
  корневых сертификатов (как выгрузить — `docs/desktop-setup.md`); проверка: `node -e "fetch('https://api.mistral.ai/v1/models').then(r=>console.log(r.status))"`.
  Разбор можно прогнать и без веб-приложения: `npx tsx src/scripts/run-pipeline.ts <id сессии>` (в `server/`).
- **Глубина декомпозиции** влияет только на структуру из интервью: 2 — LLM группирует операции в подпроцессы (операции
  становятся уровнем 1, как в эталоне B002), 1 — операции процесса без подпроцессов. Глубже операций уровня нет: по
  Соглашению подпроцесс делится на операции, и разворачивать эту группировку дальше приложение не будет.
- **Роли пользователей** — аутентификация API есть, но нет разграничения прав (аналитик/владелец/руководитель): все вошедшие равны.
- **Совместная работа** — защита от потерянных правок (409 при устаревшей версии и черновик для повторного применения), но без совместного редактирования в реальном времени.
- **Soundness-анализ BPMN** — перебор состояний игры токенов (`shared/soundness.ts`), а не полный анализ сетей Петри: условия на стрелках не вычисляются (возможна любая ветка), включающее слияние упрощено, непрерывающее граничное событие моделируется как «ветка есть или нет»; диаграмма, где достижимо больше 20 000 состояний (около 15 параллельных веток), не разбирается — остаётся проверка цикла без выхода.
- **PDF-альбом** — через Playwright/Chromium, если браузер доступен; иначе HTML для печати.
- **Импорт в Business Studio / ELMA365 / Ramus** — не проверялся; экспорт — строгое подмножество BPMN 2.0, совместимое с bpmn.io и Camunda Modeler.

## API (кратко)

Смотрите `server/src/routes/*.ts`. Основные группы:
- `POST /api/auth/login|logout`, `GET /api/auth/me` — вход;
- `POST/GET /api/sessions` — сессии моделирования;
- `POST /api/sessions/:id/ingest-text|upload`, `POST /api/sessions/:id/run` (202 + задача), `GET /api/jobs/:id` — обработка текста;
- `POST /api/sessions/:id/interview/*` — режим Б;
- `PUT /api/sessions/:id/model` (заголовок `X-Base-Updated-At`), `POST /api/sessions/:id/rebuild-diagrams` — редактирование и пересборка;
- `GET /api/sessions/:id/export/*` — экспорт;
- `GET /api/schema/process-logic/latest` — контракт промежуточной модели для внешних систем (6.4).
