# Система построения моделей IDEF0 и BPMN по текстовому интервью

Веб-приложение, реализующее техническое задание: преобразование текстового интервью с владельцем бизнес-процесса в формализованные модели IDEF0 и BPMN 2.0, с трассировкой каждого элемента к исходному тексту.

## Состав репозитория

```
server/   — API-сервер (Express + TypeScript + SQLite), конвейер извлечения/валидации/генерации
web/      — веб-клиент (React + TypeScript + Vite), редактор и просмотр моделей
docker-compose.yml — запуск обоих сервисов в контейнерах (НФТ-6)
```

## Архитектура (раздел 6 ТЗ)

- **Веб-клиент** — чат интервью, просмотр текста с трассировкой, просмотрщик BPMN (bpmn.io/bpmn-js) и IDEF0 (SVG), список пробелов, панель валидации, экспорт.
- **API-сервер** — REST API, хранилище сессий (SQLite).
- **Оркестратор LLM-конвейера** — `server/src/pipeline/extract.ts`: фрагментация → чанки → вызов LLM со structured output → слияние и дедупликация сущностей.
- **Модуль валидации** — `server/src/pipeline/validate.ts` (BPMN soundness-lite, правила IDEF0, стиль наименований).
- **Модуль пробелов** — `server/src/pipeline/gaps.ts` (правила полноты, противоречия, неявные ветвления).
- **Модуль раскладки и генерации** — `server/src/pipeline/bpmn.ts` (детерминированная генерация BPMN 2.0 XML + layered layout), `server/src/pipeline/idef0.ts` (SVG IDEF0: контекст A-0, декомпозиция A0, узловое дерево).
- **Принцип** (6.2): LLM только извлекает данные и формулирует факты с цитатами; нотации, раскладка и валидация строятся детерминированным кодом — LLM не участвует в генерации диаграмм.

Промежуточная модель — **Process Logic JSON** (раздел 5 ТЗ) — реализована как:
- TypeScript-типы + zod-схема: `server/src/types/model.ts`;
- публикуемый JSON Schema контракт: `server/src/schema/process-logic.schema.json`, отдаётся по `GET /api/schema/process-logic.json`.

## LLM-провайдер (ФТ-3, 6.3)

Провайдер подключаемый (`server/src/llm/provider.ts`):
- если задан `ANTHROPIC_API_KEY` — используется Claude (structured output через tool-use, `temperature=0` — НФТ-3 воспроизводимость);
- если ключ не задан — используется **детерминированный офлайн-экстрактор** на правилах и словарях (`server/src/llm/mockProvider.ts`). Это осознанный fallback для работы без сети (НФТ-4 «режим без передачи данных наружу») и для тестирования конвейера без внешних зависимостей. Качество извлечения у офлайн-режима существенно ниже, чем у LLM — для реального применения нужен ключ.

## Быстрый старт (разработка)

Требуется Node.js 22+.

```bash
# сервер
cd server
npm install
npm run dev      # http://localhost:8787

# в другом терминале — клиент
cd web
npm install
npm run dev       # http://localhost:5173 (проксирует /api на 8787)
```

Опционально — включить LLM-извлечение вместо офлайн-режима:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

## Запуск через Docker Compose (НФТ-6)

```bash
cp .env.example .env   # при желании укажите ANTHROPIC_API_KEY
docker compose up --build
```

Клиент — `http://localhost:8080`, API — проксируется nginx на `/api`. Данные сессий хранятся в volume `server_data` (SQLite).

## Покрытие функциональных требований

| Раздел ТЗ | Реализация |
|---|---|
| ФТ-1 Предобработка | `pipeline/fragment.ts` — фрагментация, определение спикера, нормализация по словарю (`/api/glossary`), обезличивание ФИО |
| ФТ-2 Интерактивное интервью | `pipeline/interviewEngine.ts` + `routes/interview.ts` — сценарий, приоритизация вопросов, живое превью BPMN, отметка неверных элементов, ограничитель повторов, протокол |
| ФТ-3 Извлечение структуры | `pipeline/extract.ts` + `llm/*` — structured output, цитаты, уверенность, статус «гипотеза», классификация AS-IS/TO-BE/проблема |
| ФТ-4 Пробелы и противоречия | `pipeline/gaps.ts` — правила полноты, противоречия исполнителей, неявные ветвления, приоритеты, лист вопросов |
| ФТ-5 Валидация | `pipeline/validate.ts` — старт/конец, недостижимые узлы, тупики, циклы без выхода, число блоков IDEF0, управление/выход, стиль наименований |
| ФТ-6 Генерация BPMN | `pipeline/bpmn.ts` + `pipeline/layout.ts` — пул/дорожки, типы задач/событий/шлюзов, объекты данных, авто-раскладка слева направо |
| ФТ-7 Генерация IDEF0 | `pipeline/idef0.ts` — A-0, A0, диагональная раскладка, ICOM-стрелки, узловое дерево, draw.io экспорт |
| ФТ-8 Согласованность нотаций | Обе нотации строятся из одной модели; правка модели помечает диаграммы «к пересборке» (`diagramsStale`) |
| ФТ-9 Редактор и трассировка | Просмотр BPMN/IDEF0, список модели с инлайн-правкой имени/исполнителя, клик по элементу → подсветка цитаты в тексте, фильтр гипотез/уверенности, версии и diff, комментарии |
| ФТ-10 Экспорт | `.bpmn`, IDEF0 `.svg`/`.drawio`, JSON модели, лист вопросов, протокол интервью, проблемы/предложения TO-BE, HTML/PDF-альбом |
| ФТ-11 Шаблоны и справочники | `/api/templates` (сценарии интервью), `/api/glossary` (словарь терминов/ролей) |

## Известные ограничения (честно, для прозрачности)

- **Офлайн-экстрактор** — эвристика на регулярных выражениях и словарях; для качества, заявленного в критериях приёмки (recall/precision), нужен реальный LLM-провайдер (`ANTHROPIC_API_KEY`).
- **Редактор диаграмм** — просмотр через bpmn-js (Viewer) и SVG для IDEF0 с трассировкой и инлайн-правкой списком; полноценный canvas-редактор с drag-and-drop (bpmn-js Modeler) не подключён — правки вносятся через панель «Модель» и автоматически помечают диаграммы к пересборке.
- **Soundness-анализ BPMN** — упрощённая проверка (недостижимые узлы, тупики, циклы без выхода), а не полноценный анализ сетей Петри.
- **PDF-альбом** — рендерится через Playwright/Chromium, если браузер доступен в окружении; иначе экспортируется HTML-версия для печати в PDF из браузера.
- **RBAC и шифрование хранилища** — не реализованы (однопользовательский демонстрационный контур); ролевая модель (аналитик/владелец/руководитель/администратор) заложена в ТЗ, но авторизация в MVP не выполнена.
- **Импорт в Business Studio / ELMA365 / Ramus** — не проверялся (требует тестового стенда, этап 0 ТЗ); экспорт ориентирован на строгое подмножество BPMN 2.0, совместимое с bpmn.io и Camunda Modeler.

## API (кратко)

Смотрите `server/src/routes/*.ts`. Основные группы:
- `POST/GET /api/sessions` — управление сессиями моделирования;
- `POST /api/sessions/:id/ingest-text|upload`, `POST /api/sessions/:id/run` — режим А;
- `POST /api/sessions/:id/interview/*` — режим Б;
- `PUT /api/sessions/:id/model`, `POST /api/sessions/:id/rebuild-diagrams` — редактирование и пересборка;
- `GET /api/sessions/:id/export/*` — экспорт;
- `GET /api/schema/process-logic.json` — контракт промежуточной модели для внешних систем (6.4).
