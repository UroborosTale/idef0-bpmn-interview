# Ручная приёмка: что посмотреть глазами

Список собран из истории чатов Claude Code (см. `docs/claude-code-history/`). В переписке почти каждый пункт
заканчивается фразой «тесты проходят, вживую не проверял» — этот файл и есть то, что осталось посмотреть один раз
руками. Отмечайте статус прямо здесь.

## Как проверять

```bash
npm run typecheck          # типы
npm test                   # тесты сервера и клиента
npm run test:e2e           # сквозные (браузер: Edge на Windows)
```

Настольное приложение (Visio внутри окна) — см. `docs/desktop-setup.md`. Быстрая самопроверка оболочки, без участия
человека: она рисует фигуры в Visio, принимает правки, переключает страницы и пишет отчёт со скриншотами.

## Известные проблемы (проверено, не работает)

**«Режим Г» в настольном приложении (рисовать с нуля).** В веб-версии режим работает, в настольной — фигуры,
нарисованные в Visio, в модель не попадали, и приложение об этом молчало. Разбор от 15.10, по важности:

1. ~~новые фигуры принимаются только со страницы операции, а общая схема пропускается~~ — **ИСПРАВЛЕНО 16.10.2026.**
   Было: `server/src/pipeline/vsdxImport.ts` (`if (n.pmId || !page.scope || !nodeById.has(page.scope)) continue;`).
   У общей схемы метки `pm_scope` нет по устройству выгрузки (`export/vsdx.ts`), а шаги общей схемы в модели и так идут
   без `bpmn_scope` (`types/model.ts`) — то есть отсутствие метки не означало «чужое». Теперь фигуры с общей схемы
   становятся шагами верхнего уровня (`bpmn_scope: null`), а шаги со страницы операции работают как раньше. Заодно
   заглушки выгрузки «Начало процесса» / «Завершение процесса» (метка `pm_k = synth`) явно исключены из приёма, иначе
   первый же приём правок создал бы два события из ничего. Тесты: `server/test/vsdxReconcile.test.ts` — «новая фигура
   на общей схеме процесса…» и «режим „рисовать с нуля“…»; проверено через живой API: пустая сессия → фигура на общей
   схеме → приём правок → в модели один шаг, заглушек нет.
2. ~~нельзя создать исполнителя с диаграммы: кнопка «Исполнители» в палитре открывает пустое меню без пункта «Новый…»~~ —
   **ИСПРАВЛЕНО 16.10.2026 (создание).** В палитре существующих объектов у «Исполнителей» и «Нормативных документов»
   появилась группа «Новый»: «Новый исполнитель…» и «Новый нормативный документ…». Объект создаётся тем же помощником, что
   и в справочниках (`dict-ops.addEntry`) и сразу привязывается к выбранному шагу: исполнитель становится его исполнителем
   (а значит, даёт дорожку на диаграмме BPMN), нормативный документ — управлением. Тесты: `shellSelection.test.tsx`
   («палитра: у исполнителей и нормативных документов есть „Новый…“»). Заодно ветки палитры для документов и программных
   продуктов переведены на тот же помощник — раньше они собирали запись вручную.
   **Что осталось:** палитра существующих объектов работает только в настольном приложении — меню строится через
   `showShellMenu` (окно Windows поверх Visio), а в браузере у этого вызова нет запасного варианта, поэтому кнопки второй
   группы в веб-версии ничего не делают. Лечится общим HTML-меню-фолбэком (`showShellMenu` при отсутствии оболочки
   должен рисовать меню сам, как это делает палитра для типов событий).
3. ~~на IDEF0 в Visio нет палитры, новые блоки IDEF0 приём правок не берёт~~ — **ИСПРАВЛЕНО 16.10.2026 (требуется
   пересборка exe).** Рисование на диаграммах IDEF0 заработало целиком:
   - **Палитра.** На вкладке IDEF0 теперь показывается палитра с кнопкой «Блок функции» (перетащить или щёлкнуть) и
     инструментом «Соединительная линия» (штатный инструмент Visio: стрелка приклеивается к блокам). Группа объектов
     BPMN (документы, системы, роли) на IDEF0 скрыта — она относится к выбранному шагу.
   - **Блок.** `VisioPane.SpecFor("idef0-fn")` рисует прямоугольник 170 × 90 с заливкой блока выгрузки (`#e8eef7`) и
     текстом «Новая функция»; размеры совпадают с `shared/idef0Layout` (BLOCK_W/BLOCK_H). Название правится в Visio.
   - **Приём правок.** Сервер (`applyIdef0Edits`) создаёт функции по блокам без меток и стрелки ICOM по соединителям.
     Вид стрелки определяется по стороне блока, к которой приклеен конец (как в IDEF0): сверху — управление,
     слева — вход, снизу — механизм (роль), справа — выход; стрелка из правой стороны одного блока в левую другого —
     связь «выход → вход» (одна сущность в выходах источника и входах потребителя). Сущности создаются по подписи
     стрелки, если такой ещё нет: данные — для входа, выхода и связи, регламент — для управления, роль — для механизма.
     Стрелки с одним неприклеенным концом тоже читаются: выход блока в пустое место и вход «снаружи».
   - **Метки.** После приёма оболочка помечает созданные фигуры (`VisioPane.TagCreatedIdef0`): блоки — `pm_k = fn`,
     `pm_id`, `pm_n`; стрелки — `pm_k = arrow`, `pm_id`, `pm_a` («вид|функция|сущность»), `pm_n`. В манифест страницы
     пишутся ключи `fn`/`ar`, поэтому повторный приём не создаёт дубликатов, а удалённое в Visio видно как «удалено».
     Помеченные стрелки IDEF0 разбор больше не считает новыми.
   - **Тесты:** `server/test/vsdxReconcile.test.ts` — «блоки становятся функциями, а стрелки — входом, управлением,
     выходом и связью по стороне блока»; «блок на странице декомпозиции становится подфункцией; на контекстной не
     создаётся». Разбор на страницах IDEF0 теперь считает прямоугольник блоком даже без стрелок (на BPMN правило
     прежнее: без связей фигура — примечание).
   - **Не сделано / ограничения:** положение блока из Visio не переносится — раскладку IDEF0 считает приложение
     (как и в редакторе: блоки не ставятся вручную), поэтому после приёма блок встанет по раскладке; на контекстной
     диаграмме (A-0) новые блоки не создаются (там один блок процесса); безымянные стрелки пропускаются (сущности
     нечего дать название); механизм всегда становится ролью (система-механизм не создаётся, если её нет в справочнике).
4. ~~«+ Функция» не сохраняет модель: Visio пуст до «Сохранить», имя не спрашивается~~ — **ИСПРАВЛЕНО 16.10.2026
   (сохранение).** Причина была не в самой кнопке: правки структуры из студии («+ Функция», перенос, переименование,
   удаление) не записывались, а оболочка перечитывает `.vsdx` только по смене `updatedAt` сессии. Теперь в настольном
   приложении студия сама сохраняет черновик через 0,5 с после такой правки (`Studio.tsx`), в браузере поведение прежнее
   (там черновик и явное сохранение). Осталось: имя функции по-прежнему «Новая функция» и не спрашивается — переименование
   через F2 или двойным щелчком.
5. заглушки «Начало/Завершение процесса» выглядят как настоящие события, но в модель не попадают (шагами из них уже
   не становятся, но и стрелка к заглушке в модель не переносится — решить, нужно ли делать из заглушки настоящее
   событие, когда к ней провели стрелку);
6. ~~фигура из палитры встаёт в центр окна и закрывает уже стоящую там~~ — **ИСПРАВЛЕНО 16.10.2026** в оболочке
   (`VisioPane.FreeSpot`): при щелчке по кнопке палитры (без перетаскивания) фигура ищется свободное место — центр окна,
   а если он занят, шаг вправо до первого свободного. **Нужна пересборка exe:** пока открыто окно приложения, файл занят;
   порядок — закрыть окно, `dotnet build -c Release`, запустить снова (`docs/desktop-setup.md`).
7. ~~в форме создания нет кода процесса (вида `B002.00.00`)~~ — **ИСПРАВЛЕНО 16.10.2026.** Поле «Код процесса» появилось
   на странице «Новая сессия»: значение приводится к виду `B002.00.00` (принимаются «B2», «Б2», «B002.00.00»),
   сохраняется в `meta` и попадает в модель процесса (режимы А, Б, В, Г) — по коду работают нумерация по Соглашению и
   диаграммы операций. Если извлечение из текста нашло свой код, он главнее.
8. ~~мелочи: сессия Г хранится как режим А (метка «Текст», лишняя вкладка), после приёма правок висит баннер
   «Пересобрать диаграммы»~~ — **ИСПРАВЛЕНО 16.10.2026.** У сессии «рисовать с нуля» теперь свой режим `blank`: в списке
   отметка «С нуля» (а не «Текст»), вкладки «Текст» и кнопки «Перезапустить обработку текста» нет, в протоколе сессии
